# 流模拟控制台 (Stream Simulator)

FireGuard 流模拟控制台是一个独立的 RTSP 视频流仿真服务，用于在开发和测试环境中模拟真实摄像头的视频流推送。支持画质评估、智能转码与防呆保护。

---

## 快速启动

```bash
cd simulator
uvicorn main:app --host 0.0.0.0 --port 8001 --reload
```

访问 [http://localhost:8001](http://localhost:8001) 打开控制台界面。

## 核心功能

### 1. 视频上传与元数据解析

上传视频文件后，系统自动调用 `ffprobe` 提取以下元数据：

| 字段 | 来源 | 格式化 | 说明 |
|---|---|---|---|
| 文件格式 | `format.format_name` | 大写 (MP4, MKV) | 原始容器格式 |
| 文件大小 | `format.size` | MB/GB | 物理体积 |
| 视频时长 | `format.duration` | MM:SS | 视频总时长 |
| 分辨率 | `streams[v].width × height` | 智能标签 (1080P) | 前端自动识别分辨率等级 |
| 帧率 | `streams[v].avg_frame_rate` | fps | 计算 BPP 必用字段 |
| 总码率 | `format.bit_rate` | Mbps | 决定画质的核心参数 |
| 视频编码 | `streams[v].codec_name` | H.264, HEVC | 源编码格式 |
| 音频编码 | `streams[a].codec_name` | AAC, MP3 | 源音频格式 |

### 2. BPP 画质评估

系统基于 **BPP (Bits Per Pixel)** 对源文件进行画质评级：

```
BPP = 总码率(bps) / (宽 × 高 × 帧率)
```

> **注**: 若源文件为 H.265/HEVC，由于其高压缩率，计算出的 BPP 需乘以 **1.6 倍**后再参与评级。

#### 评级标准

| BPP 区间 | 系统评级 | 前端标签 | 颜色 | 可用转码档位 | 处理策略 |
|---|---|---|---|---|---|
| < 0.05 | `GRADE_POOR` | 画质极低 | 红色 | Copy, 流畅 | 限制转换：禁用高清选项，防止放大马赛克 |
| 0.05 ~ 0.1 | `GRADE_FAIR` | 标准画质 | 橙色 | Copy, 流畅, 标准 | 常规处理：允许流畅或标准导出 |
| 0.1 ~ 0.2 | `GRADE_GOOD` | 高清画质 | 绿色 | 全量开放 | 允许所有质量选项（含超清） |
| > 0.2 | `GRADE_EXCELLENT` | 极高画质 | 蓝色 | 全量开放 | 强烈建议转码瘦身，即使选高清也走 CRF 压缩 |

### 3. 全维度推流自定义 (New)

不再受限于固定档位，用户可以对每一个推流任务进行精细化配置：

- **视频编码 (vcodec)**: 支持 `Copy` (原样转发)、`libx264` (H.264) 和 `libx265` (H.265)。
- **音频编码 (acodec)**: 支持 `Copy`、`AAC` 转码或 `None` (静音)。
- **分辨率 (Resolution)**: 提供从 4K 到 240P 的 8 档预设，支持一键切换。
- **帧率 (FPS)**: 支持 60 到 5 FPS，满足高清流畅或窄带延时模拟。
- **视频码率 (Bitrate)**: 提供 8 Mbps 到 100 Kbps 的多档位选择。
- **编码预设 (Preset)**: 支持从 `ultrafast` 到 `slow` 的速度与质量平衡调节。

### 4. 独占显示与资源保护

为防止同一视频源被重复推流导致端口或进程冲突，系统引入了**独占显示逻辑**：
- **自动隐藏**: 视频一旦开始推流，将从“视频库”中自动消失。
- **自动归还**: 停止推流后，视频文件会即时重现在“视频库”中供重新配置。

### 5. 一键快捷复制

活动流列表中提供地址快捷复制按钮，点击即可获取 RTSP URL，方便在 VLC、FFplay 或后端配置中快速粘贴。

### 元数据展示

每个视频源文件展示 7 项核心元数据：

- **分辨率**: 智能标签 (4K/1080P/720P/480P) + 精确数值
- **编码**: 源视频编码格式 (H.264/H.265/MPEG-4 等)
- **帧率**: fps 数值
- **码率**: Mbps 数值
- **时长**: MM:SS 格式
- **大小**: MB/GB 格式
- **格式**: 容器格式 (MP4/MKV/AVI)

### 画质评估展示

- **BPP 进度条**: 可视化展示 BPP 值，颜色随画质等级变化
- **评级徽章**: 带颜色区分的等级标签 (红/橙/绿/蓝)
- **质量提示**: 根据评级显示处理建议文案

## 技术实现

### 核心文件

| 文件 | 职责 |
|---|---|
| `simulator/main.py` | FastAPI 服务入口，包含上传、解析、画质评估逻辑 |
| `simulator/manager.py` | StreamManager，管理 FFmpeg 推流进程 |
| `simulator/bin/mediamtx.exe` | MediaMTX RTSP 服务器 |
| `simulator/bin/ffmpeg.exe` | FFmpeg 视频处理工具 |

### 关键函数

- `probe_video(video_path)`: 调用 ffprobe 提取完整元数据
- `evaluate_quality(bpp)`: 基于 BPP 计算画质评级
- `StreamManager.start_stream()`: 启动 FFmpeg 推流进程，支持 5 档编码选项

### 依赖

- Python 3.9+
- FastAPI + Uvicorn
- FFmpeg (内置)
- MediaMTX (内置)

## 常见问题

### Q: 为什么我的视频没有"超清"选项？

A: 系统根据源文件 BPP 评级自动限制可用档位。如果源文件画质评级为 `GRADE_FAIR`（标准画质）或更低，超清选项会被自动隐藏。只有 `GRADE_GOOD`（高清画质）及以上评级才开放超清选项。

### Q: Copy 模式和转码模式有什么区别？

A: Copy 模式直接转发源文件编码，零重新编码，100% 无损。转码模式会重新编码为 H.264，可以控制画质/体积平衡，但会引入轻微画质损失和编码耗时。

### Q: 如何选择最合适的转码档位？

A: 
- 源文件画质好且需要压缩体积 → 选"标准"或"高清"
- 源文件画质一般 → 选"标准"
- 源文件画质差 → 选"流畅"或直接 Copy
- 需要归档或证据级画质 → 选"超清"

### Q: 推流后检测端画面撕裂怎么办？

A: 优先尝试使用 **Copy 模式**，直接转发源编码，零损耗零延迟。如果源编码不兼容，再选择转码模式。
