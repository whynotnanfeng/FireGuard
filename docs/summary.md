# 项目总结与交付报告

## 1. 核心工作回顾

本项目已完成从原型机到企业级火灾监测平台的关键演进。

### V5.1 服务端帧嵌入渲染 (2026-05-19)
经过 V5.0 Canvas overlay 方案（客户端渲染）的数轮调试，最终确认 hls.js 的 ~6s 缓冲延迟导致检测框与画面永远存在时间偏移。V5.1 恢复服务端帧嵌入渲染：
- **检测框嵌入**：`AnnotatedHLSWriter` 使用 NVENC 将框直接绘制到 H.264 帧中，帧精确对齐
- **性能优化**：720p@10fps 标注流，编码负载仅为旧版 1080p@15fps 的 30%
- **GPU 全链路**：NVDEC 解码 + CUDA 推理 + NVENC 编码，CPU 瓶颈已解除
- **采集韧性**：指数退避重连，移除 STALL 自动停止，支持长时间无目标场景

### 五位一体同步
系统实现"画面、进度条左侧时间、右侧检测记录、画面检测框、进度条位置"完全对齐：
- **V5.1 服务端渲染**：框嵌入视频帧内，物理上不可能出现偏移
- **流切换保护**：`isSwitchingStream` 期间阻止时间更新，`jumpToLive()` 清空检测状态
- **历史检测框全量加载**：从 DB 加载，缓冲池容量 300

### 配置中心与 GPU 推理 (v1.9.0)
系统引入了基于 Redis 的统一配置中心，解决了多服务间端口硬编码与路径管理问题：
- **ServiceRegistry**：提供配置管理、服务注册发现、go2rtc 路径管理三大核心能力。
- **动态端口管理**：所有服务端口从 Redis 读取，一处修改全局生效。
- **GPU 推理支持**：任务级 GPU 选择，CUDAExecutionProvider 加速，前端环境检测。
- **稳定性增强**：ElasticScaling 冷却期、检测框持久化、HLS 缓冲优化、RTSP 代理就绪等待。

### MediaMTX 流媒体网关迁移 (v2.0.0)
系统流媒体网关从 go2rtc 全面迁移至 **MediaMTX v1.18.1**：
- **端口分离**：RTSP 端口 (8554)、HLS 端口 (8888)、WebRTC 端口 (8889) 分离，消除协议冲突。
- **动态流注册**：使用 `POST /api/v1/paths` API 动态创建流路径，FFmpeg 推流前流路径已就绪。
- **FFmpeg 视频采集器**：引入 FFmpegCapture 模块替代 OpenCV VideoCapture，彻底解决 Windows 环境下视频流不稳定问题。

### MediaMTX 流生命周期管理 (v2.1.2)
系统修复了第二次任务执行时卡死在初始化的关键问题：
- **显式拉流路径注册**：通过 `/v3/config/paths/add/{stream_path}` API 配置路径的 `source` 为原始 RTSP 地址，使 MediaMTX 主动从摄像头拉流。
- **彻底清理机制**：任务停止时先踢出连接 (`/v3/paths/{stream_path}/kick`) 再删除路径配置 (`/v3/config/paths/delete/{stream_path}`)，确保路径完全清理。
- **效果**：第二次任务启动时，MediaMTX 自动从原始 RTSP 源拉流，FFmpegCapture 正常读取帧，不再卡死在初始化。

### UI 框架全面重构 (Migrated to Ant Design Vue)
前端架构从 Element Plus 迁移至 **Ant Design Vue 4.x**。
- **提升点**: 更加严谨的组件类型系统、更符合现代化管理后台的 UI 视觉（亮色系方案）、以及更好的响应式表格性能。

### 2.9 双 URL HLS 架构与 Session 录制 (v1.2.5 Dual-HLS Edition)

本阶段彻底解决了直播白屏、回放黑屏和进度条定位异常三大顽疾，引入了直播/回放分离的双 URL 架构。

#### 核心改进
- [x] **双 URL HLS 架构**：
    - **直播模式**：`initLiveHls()` 使用 `/api/storage/{id}/live/index.m3u8` 直接读取 FFmpeg 实时写入的 m3u8，消除了合并 playlist 在任务启动初期返回空内容导致的白屏问题。
    - **回放模式**：`initVodHls()` 使用 `/api/tasks/{id}/stream.m3u8?mode=vod` 加载合并所有 session 的 VOD 流，`#EXT-X-ENDLIST` 标签使 hls.js 支持任意位置 seek，解决了拖动进度条黑屏和停止任务后历史监控黑屏的问题。
- [x] **Session 录制管理**：
    - `StorageManager` 实现了 session-based 录制：每次任务启动创建 `live/` 目录，停止时重命名为 `session_N/`。
    - `generate_merged_m3u8()` 将所有 session 用 `#EXT-X-DISCONTINUITY` 标记拼接为统一时间轴。
    - `force_vod` 参数强制添加 `#EXT-X-ENDLIST`，使 VOD 模式可 seek。
- [x] **Elapsed-Time 进度条**：
    - 直播模式使用 `elapsed time = Date.now() - first_session_start_time` 驱动进度条，解决了 `video.duration` 为 Infinity 导致的定位异常。
    - `startLiveProgressTimer()` 以 500ms 间隔持续更新进度条位置，确保始终在最右端。
- [x] **Overlay 显示优化**：
    - 引入 `liveVideoReady` 标志，HLS 视频首次播放后隐藏加载遮罩，避免白色画面闪烁。
    - WS `running` 消息触发 HLS 重连，确保直播流恢复后视频立即显示。

#### 技术深度
- **直播/回放 URL 分离**：直播使用静态文件服务的直接 m3u8（零延迟），回放使用动态生成的合并 m3u8（完整时间轴）。这种分离避免了两种模式互相干扰。
- **Session DISCONTINUITY**：跨 session 播放时，编码参数可能不同（分辨率、帧率），`#EXT-X-DISCONTINUITY` 标记通知解码器重置状态，避免花屏或解码失败。
- **空 Playlist 降级**：直播模式下如果 FFmpeg 还没写入任何分片，后端返回一个基本的空 m3u8 playlist 而非 404，hls.js 会持续重试直到有内容可用。
