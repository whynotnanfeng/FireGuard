# 项目概览：火灾监测系统 (FireGuard) v2.7.0 "Performance Optimization Edition"

## 1. 愿景与目标

在各种高风险生产环境下，及时、准确地发现烟雾与明火是保护生命财产安全的第一道防线。**火灾监测系统 (FireGuard)** 是一款轻量级、企业级的智能 AI 视觉检测管理平台。

本系统的目标是：
- **兼容性**: 支持 ONNX 模型格式，无缝集成主流 AI 算法。
- **稳定性**: 独创 **5-3 物理隔离协议** 与 **状态防火墙** 技术，确保在极端网络环境下 UI 依然稳健且无刷新抖动。
- **视频交付**: **双 URL HLS 架构**，直播/回放分离，彻底解决白屏、黑屏和进度条定位异常。Session-based 录制支持跨时段无缝回放。
- **五位一体同步 (v1.9.5 新增)**: 画面、进度条左侧时间、右侧检测记录、画面检测框、进度条位置完全对齐。自动时间校准机制消除 HLS PTS 与系统时间的系统性偏移，检测框绝不提前显示。
- **配置中心 (v1.9.0 新增)**: 基于 Redis 的统一配置中心，动态管理服务端口、服务注册发现与 MediaMTX 路径，一处修改全局生效。
- **MediaMTX 流媒体网关 (v2.0.0 新增)**: 从 go2rtc 迁移至 MediaMTX v1.18.1，RTSP/HLS/WebRTC 端口分离，动态路径注册机制确保推流稳定。
- **MediaMTX 流生命周期管理 (v2.1.2 新增)**: 显式注册拉流路径，配置 `source` 为原始 RTSP 地址。任务停止时彻底清理路径配置，解决第二次任务执行时卡死在初始化的问题。
- **FFmpeg 视频采集器 (v2.0.0 新增)**: 引入 FFmpegCapture 模块替代 OpenCV VideoCapture，彻底解决 Windows 环境下视频流不稳定问题。循环感知 PTS 时间戳确保视频循环后检测框和检测记录继续正常显示。
- **动态端口发现 (v2.0.1 新增)**: 通过 Redis 配置中心实现服务间端口的动态发现，消除硬编码问题。后端自动查询 Simulator 实际运行端口，无需手动配置。
- **GPU 推理 (v1.9.0 新增)**: 支持 CPU/GPU 双模式推理，任务级 GPU 选择，CUDA 加速大幅降低 CPU 负载。
- **仿真工程**: 全新 **Simulator Pro v2** 控制台，采用 **Industrial Light (明亮工业风)** 设计，支持全维度参数自定义与"监控优先"布局，为开发调试提供电影级仿真流。v2.7.0 引入异步健康监控与元数据缓存，并发效率提升 2-3 倍。
- **易用性**: 提供可视化、人性化的操作界面，非技术人员也能轻松配置模型映射并启动检测。
- **实时性**: 集成流媒体快速推理技术，实现低延迟的全天候实时监控与画框分析。
- **性能优化 (v2.7.0 新增)**: 多层缓存机制（目录大小 30s TTL、m3u8 直播 1s TTL、元数据 5s TTL），热路径日志降级为 DEBUG，异步健康监控改造，API 响应时间降低 99%。

## 2. 核心应用场景

1.  **工业园/厂区监控**: 对现有监控摄像头进行 AI 赋能，实时预警工业废气或火警。
2.  **森林防灾**: 解析高空无人机巡检或固定点位监控。
3.  **实验室/仓库**: 针对存储易燃易爆物品的密闭空间进行全天候监控。

## 3. 为什么选择本系统？

### 🚀 企业级 UI 体验
系统基于 **Ant Design Vue 4.x** 重新构建，设计风格简约而专业。支持列表排序（如按照创建时间排序）、动态搜索与流体布局，确保在高并发任务下依然保持流畅的用户体验。

### 🧠 灵活的模型适配逻辑 (Label Logic)
我们深知模型的多样性。系统内置了"标签映射编辑器"，允许用户为每一个模型手动指定 `0: 烟, 1: 火` 或 `0: 背景, 1: 烟`。配合后台的"自动索引哨兵"技术，杜绝了 AI 识别内容与实际语义不符的问题。

### ⚡ 多维任务引擎
支持从单张图片、批量视频文件到网络 RTSP 流的多种检测任务类型，满足从离线分析到在线监控的全方位需求。

### 🔧 统一配置中心 (v1.9.0)
基于 Redis 的轻量级配置中心，提供动态端口管理、服务注册发现和 go2rtc 路径管理。无需类似 Nacos 的重量级方案，即可实现多服务间的配置同步与治理。

### 📡 MediaMTX 流媒体网关 (v2.0.0)
系统流媒体网关从 go2rtc 迁移至 **MediaMTX v1.18.1**，提供更稳定的 RTSP/HLS/WebRTC 流管理。RTSP (8554)、HLS (8888)、WebRTC (8889) 端口完全分离，消除协议冲突。

**v2.1.2 更新**：改为显式注册拉流路径。通过 `/v3/config/paths/add/{stream_path}` API 配置路径的 `source` 为原始 RTSP 地址，使 MediaMTX 主动从摄像头拉流。任务停止时通过 `/v3/config/paths/delete/{stream_path}` 彻底清理路径配置。

### 🎥 FFmpeg 视频采集器 (v2.0.0)
引入 **FFmpegCapture** 模块替代 OpenCV VideoCapture，通过 `subprocess.Popen` 启动 FFmpeg 子进程直接读取 RTSP 流。支持自动恢复和优雅重连，彻底解决 Windows 环境下视频流不稳定问题（检测框 50 秒后消失）。项目自带 `bin/ffmpeg.exe`，无需用户额外安装。v2.0.1 起使用循环感知 PTS 时间戳，视频循环后检测框和检测记录继续正常显示。

### 🔌 动态端口发现 (v2.0.1)
通过 Redis 配置中心实现服务间端口的动态发现。Simulator 启动时自动注册端口信息，后端通过 `ServiceRegistry.get_simulator_ports()` 查询实际运行端口，消除硬编码问题，支持多实例部署。

### 🎯 GPU 加速推理 (v1.9.0)
支持在创建任务时选择 GPU 推理模式，通过 CUDAExecutionProvider 将 ONNX 推理卸载至 GPU，大幅降低 CPU 负载，提升系统整体吞吐量。
